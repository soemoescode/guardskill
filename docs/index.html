A repository can run code the moment your agent opens it.

Git reads core.fsmonitor and a dozen similar keys from the project's own .git/config, and coding agents run git status before you have typed anything. GuardSkill reads those settings first and tells you what is in them.

$npx guardskill . no install · no account · reads only

What actually happens

A project arrives as a zip from a client, a folder on a shared drive, an archive your agent unpacked. Somewhere in it sits a line like this:

.git/config
[core]
        repositoryformatversion = 0
        fsmonitor = /tmp/.cache/fsmonitor-helper.sh

Git invokes that command while refreshing the index — during git status, git diff, git add. It runs with your privileges, outside any sandbox, before a single prompt reaches you.

Manifold Security found eight of these issues across seven coding agents, and their note on delivery is the part most people miss: cloning a hostile URL does not trigger it, because .git/config never travels with a clone. The project has to arrive as files. And CVE-2026-45033 in GitHub Copilot CLI (CVSS 8.5) shows that a single bare repository hidden in a subdirectory is enough on its own — git finds it while walking the tree and applies its config.

What it checks

Direct execution
core.fsmonitor, core.sshCommand, core.gitProxy, core.pager, core.editor, sequence.editor, diff.external, uploadpack.packObjectsHook
Indirect execution
filter.*.clean/smudge/process, diff.*.textconv, merge.*.driver, mergetool.*.cmd, credential.helper
Shell aliases
any alias.* whose value starts with !
Deferred config
include.path and includeIf.*.path, which can introduce any of the above later
Hooks
core.hooksPath overrides, active scripts in .git/hooks, and hooks that pipe a download into a shell or decode base64 before running it
Structure
bare repositories anywhere in the tree, nested .git directories that are not registered submodules

Why it does not cry wolf

29clean repositories that must stay silent
22attack patterns that must each be caught
0runtime dependencies

A security tool that flags every project gets uninstalled in a week. husky, lefthook, git-lfs, git-crypt, registered submodules, credential helpers and custom pagers all appear in the clean fixture set, and the build fails if any of them produces a finding above informational. The suite also fails if a hostile fixture is caught by the wrong rule — catching it for the wrong reason is not catching it.

Recognised hook managers are reported as informational, not as a risk — but GuardSkill still reads the scripts, and escalates to critical if one of them fetches or decodes code before it runs.

What it will not do

It never writes to the project it scans and never executes anything it finds. It makes no network calls and collects no telemetry, so it behaves identically offline. It has no dependencies, so installing it does not pull in a supply chain of its own. And it does not follow symlinks — a link inside a hostile repository cannot walk the scanner out of its target.

It is a signal, not a verdict. Every finding shows the file, the line and the exact value, so you decide.
